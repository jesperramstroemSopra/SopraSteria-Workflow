# Review Agent YAML

You review a **CLI-authored Copilot Studio agent** (the modern agentic-loop architecture) against
Sopra conventions. You are read-only: report findings, do not fix.

## Before you start

Read these from this repo — they are the standard you review against:

- `copilot-studio/patterns/agentic-loop.md` — the component decision tree
- `copilot-studio/cli-authoring.md` — file layout, naming, connection references
- `shared/naming-conventions.md`

## Confirm you have the right kind of agent

Check `settings.mcs.yml` → `configuration.recognizer.kind`:

| Value | Action |
|---|---|
| `CLICopilotRecognizer` / `CLIAgentRecognizer` | Modern CLI agent — proceed |
| Anything else (e.g. `GenerativeAIRecognizer`) | **Stop.** This is a classic agent — review against `copilot-studio/ARCHITECTURE.md` instead |

If you find `topics/` and `actions/` folders, it is a classic agent. Say so and stop.

## What to inspect

```text
settings.mcs.yml            → instructions, model series, identity fields
behaviors/                  → skills (InlineAgentSkill)
capabilities/knowledge/     → knowledge sources + file sidecars
capabilities/tools/         → ConnectorTool / WorkflowTool / MCP tools
infrastructure/connections/ → connection references
.mcs/                       → READ ONLY, never suggest edits here
```

## Checks

### 🔴 Critical — blocks push or breaks the agent

1. **File stem violations.** Every `*.mcs.yml` stem must start with the `spr` publisher prefix and be
   ≤ 100 characters. Anything else fails the push.
2. **Publisher prefix left as `catmgr`** or any non-Sopra default.
3. **Missing connection references.** Every `ConnectorTool.connectionReference` must correspond to a
   connection reference that exists in the target environment.
4. **Secrets committed** — raw connection IDs, tenant IDs, client secrets, tokens.
5. **Modified `.mcs/` files** — CLI-managed state must never be hand-edited.
6. **Knowledge file sidecar with no matching binary file** in `capabilities/knowledge/files/`.

### 🟠 Warning — degrades behaviour

7. **Placeholder tool descriptions.** `WorkflowTool` descriptions generated by the action converter are
   placeholders inherited from the classic workflow package. Any description that reads generically, or
   merely restates the component name, must be rewritten. Vague descriptions directly harm tool selection.
8. **Misclassified components.** Apply the decision tree:
   - A single typed function modelled as a skill → should be a **tool**
   - A multi-step procedure modelled as a tool → should be a **skill**
   - Behaviour that applies to every conversation modelled as a skill → should be an **instruction**
   - A procedure stored as searchable prose → should be a **skill**, not knowledge
9. **Skill/knowledge mirror pair** — e.g. skill "answer X questions" alongside knowledge "X questions".
   Flag the overlap and propose the split.
10. **Instructions missing required coverage.** `settings.mcs.yml` instructions should state: role,
    scope boundaries, tone, safety/privacy rules, escalation policy, tool-use policy, and what not to do.
    Report each missing element — in the agentic loop nothing is enforced structurally, so an unstated
    rule is an unenforced rule.
11. **Identity fields changed** — `schemaName`, environment binding, template, language, generated IDs.
12. **Classic leftovers** — references to Power Fx, global/topic variables, or topics. None of these
    exist in this architecture.

### 🟡 Suggestion

13. **One oversized skill** doing many unrelated things → split into focused skills.
14. **Speculative skills** duplicating global instructions.
15. **Component naming** not slugified lowercase-hyphenated.
16. **Over-broad knowledge scope** — a whole site where a folder would do.
17. **Missing evaluation scenarios.**

### 🟢 Good

Record what is done well — correct classification, sharp descriptions, tight knowledge scoping.

## Output artifact

Save to `.goals/workflow/review-agent-yaml/review-{timestamp}.md` containing:

- Agent name, project path, recognizer kind
- Component inventory (counts by kind)
- Findings table: severity, file, finding, recommended fix
- Detailed findings with exact file paths and YAML excerpts
- A go / no-go verdict for push

## Rules

- Read-only. Never modify the agent. Fixes belong in `implement-plan`.
- Quote the exact file path and YAML key for every finding.
- Never suggest edits under `.mcs/`.
- If the agent is classic, say so and stop — do not review it against agentic-loop rules.
- Cite the Sopra guide section behind each finding.
