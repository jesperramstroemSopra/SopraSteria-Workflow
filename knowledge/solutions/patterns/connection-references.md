# Pattern: Connection References

> **Architecture track:** Solutions / ALM
> **When to load:** Before configuring connections in any solution, or when a deployed solution has failing flows due to connection issues.

---

## What Connection References Are

A **Connection Reference** is a solution component that represents a connection to a connector. Instead of a flow hardcoding a specific connection, it references the connection reference — which is bound to an actual connection per environment.

```
Flow → Connection Reference → [bound to] → Connection (per environment)
```

This separation means:
- The same flow/connector configuration travels in the solution.
- Each environment has its own connection bound to its own service account.
- Changing a connection in one environment does not affect others.

Connection references are **mandatory** for solutions promoted across environments. Hardcoded connections break on import.

---

## Creating Connection References

Connection references are created automatically when you add a connector action to a flow inside a solution. Power Automate creates a connection reference in the solution automatically.

**Verify the connection reference is in your solution:**
1. Open the solution.
2. Check Objects → Connection References.
3. Every connector used by a flow in the solution must have a connection reference listed.

If a connection reference is missing, the connector was added outside the solution context and must be fixed before promoting.

---

## Naming Convention

```
[ProjectPrefix] [Connector Name] Connection
Examples:
  SPR SharePoint Connection
  SPR Dataverse Connection
  SPR Custom API Connection
```

The default name generated by Power Automate is usually fine; rename only if multiple connections
to the same connector exist (e.g., two different SharePoint tenants).

---

## Binding After Import

When a solution is imported into a new environment, **every connection reference must be bound**
to an existing connection before flows will run.

### During Import (Recommended)

The import wizard prompts for connection binding. Pre-create the connections in the target environment
before importing so they are available to select.

### After Import (Fix-up)

If a solution was imported without binding:
1. Open the solution in the target environment.
2. Objects → Connection References.
3. For each unbound reference: click Edit → select or create a connection.
4. Enable any flows that were disabled due to missing connections.

### Service Account Connections

All connections in Test/UAT/Prod must use the **service account** — not a consultant's personal account.

| Environment | Connection Owner |
|---|---|
| DEV | Developer personal account (acceptable) |
| TEST | Service account |
| UAT | Service account |
| PROD | Service account |

Document which service account owns each connection in the deployment runbook.

## Deployment Runbook Template

Include a connection reference section in every environment's deployment runbook:

```markdown
## Connection References — [Environment Name]

| Connection Reference | Connector | Service Account | Status |
|---|---|---|---|
| SPR SharePoint Connection | SharePoint | svc-sopra-prod@customer.onmicrosoft.com | ✅ Bound |
| SPR Dataverse Connection | Dataverse | svc-sopra-prod@customer.onmicrosoft.com | ✅ Bound |
| SPR Custom API Connection | [Custom Connector Name] | svc-sopra-prod@customer.onmicrosoft.com | ✅ Bound |

**Post-import checklist:**
- [ ] All connection references bound
- [ ] All flows enabled (check for flows disabled due to missing connections)
- [ ] Test: run each critical flow manually to verify connections work
```

## Common Failure Modes

| Symptom | Cause | Fix |
|---|---|---|
| Flow is off after import | Connection reference unbound | Bind the connection reference; enable the flow |
| `ConnectionFailed` error at runtime | Connection reference bound but connection invalid | Re-authenticate or replace the connection |
| Flow uses a connection not visible in the solution | Connection reference missing from solution | Add connector action inside solution context; rebuild if needed |
| Different connections in UAT and PROD unexpectedly | Connection reference bound to different accounts | Document and standardize service account across environments |
