# Review Agent YAML

You review a Copilot Studio agent against Sopra conventions. You are read-only: report findings,
do not fix. **This skill handles both agentic-loop and classic agents** — identify which one you
have first, then follow the corresponding track.

## Step 1 — Identify the architecture

Check `settings.mcs.yml` → `configuration.recognizer.kind`:

| Value | Architecture |
|---|---|
| `CLICopilotRecognizer` / `CLIAgentRecognizer` | **Agentic loop** → follow Track A below |
| Anything else (`GenerativeAIRecognizer`, absent) | **Classic** → follow Track B below |

Cross-check: `topics/` + `actions/` folders = classic. `behaviors/` + `capabilities/` = agentic loop.

State which architecture you found at the top of your report. Never mix guidance between tracks.

## Track A — Agentic-Loop Agent Review

Read before reviewing:
- `../../knowledge/copilot-studio/patterns/agentic-loop.md` — component decision tree
- `../../knowledge/copilot-studio/cli-authoring.md` — file layout, naming, connection references
- `../../knowledge/shared/naming-conventions.md`

### What to inspect

```text
settings.mcs.yml            → instructions, model series, identity fields
behaviors/                  → skills (InlineAgentSkill)
capabilities/knowledge/     → knowledge sources + file sidecars
capabilities/tools/         → ConnectorTool / WorkflowTool / MCP tools
infrastructure/connections/ → connection references
.mcs/                       → READ ONLY, never suggest edits here
```

### Checks — Track A

#### 🔴 Critical — blocks push or breaks the agent

1. **File stem violations.** Every `*.mcs.yml` stem must start with the `spr` publisher prefix and be
   ≤ 100 characters. Anything else fails the push.
2. **Publisher prefix left as `catmgr`** or any non-Sopra default.
3. **Missing connection references.** Every `ConnectorTool.connectionReference` must correspond to a
   connection reference that exists in the target environment.
4. **Secrets committed** — raw connection IDs, tenant IDs, client secrets, tokens.
5. **Modified `.mcs/` files** — CLI-managed state must never be hand-edited.
6. **Knowledge file sidecar with no matching binary file** in `capabilities/knowledge/files/`.

#### 🟠 Warning — degrades behaviour

7. **Placeholder tool descriptions.** `WorkflowTool` descriptions generated by the action converter are
   placeholders inherited from the classic workflow package. Any description that reads generically, or
   merely restates the component name, must be rewritten. Vague descriptions directly harm tool selection.
8. **Misclassified components.** Apply the decision tree:
   - A single typed function modelled as a skill → should be a **tool**
   - A multi-step procedure modelled as a tool → should be a **skill**
   - Behaviour that applies to every conversation modelled as a skill → should be an **instruction**
   - A procedure stored as searchable prose → should be a **skill**, not knowledge
9. **Skill/knowledge mirror pair** — e.g. skill "answer X questions" alongside knowledge "X questions".
   Flag the overlap and propose the split.
10. **Instructions missing required coverage.** `settings.mcs.yml` instructions should state: role,
    scope boundaries, tone, safety/privacy rules, escalation policy, tool-use policy, and what not to do.
    Report each missing element — in the agentic loop nothing is enforced structurally, so an unstated
    rule is an unenforced rule.
11. **Identity fields changed** — `schemaName`, environment binding, template, language, generated IDs.
12. **Classic leftovers** — references to Power Fx, global/topic variables, or topics. None of these
    exist in this architecture.

#### 🟡 Suggestion — Track A

13. **One oversized skill** doing many unrelated things → split into focused skills.
14. **Speculative skills** duplicating global instructions.
15. **Component naming** not slugified lowercase-hyphenated.
16. **Over-broad knowledge scope** — a whole site where a folder would do.
17. **Missing evaluation scenarios.**

## Track B — Classic (Topic-Based) Agent Review

Read before reviewing:
- `../../knowledge/copilot-studio/ARCHITECTURE.md` — Sopra classic architecture standard
- `../../knowledge/copilot-studio/patterns/topic-design.md` — trigger phrases, slot-filling, chaining
- `../../knowledge/copilot-studio/patterns/teams-production-hardening.md` (if deployed to Teams)
- `../../knowledge/copilot-studio/patterns/rai-error-handling.md` (if using Azure OpenAI)
- `../../knowledge/shared/naming-conventions.md`

### What to inspect

```text
topics/                     → custom topics + system topic overrides
actions/                    → connector actions, HTTP actions, AI Builder actions
settings.mcs.yml            → agent identity, auth settings, generative AI config
agent.mcs.yml               → agent manifest
```

### Checks — Track B

#### 🔴 Critical — production-blocking

1. **Hardcoded URLs or environment values** in topics or actions. All environment-specific values
   must be in environment variables (`spr_camelCase` prefix).
2. **Secrets in topic nodes** — connection credentials, API keys embedded in condition or message text.
3. **No Fallback topic customization.** The default fallback gives users a dead end. Must have
   an escalation path or ticket-creation action.
4. **Missing Entra ID auth** on a Teams-deployed agent. Manual OAuth breaks the Teams conversation
   flow — see `ARCHITECTURE.md §7`.
5. **Circular topic redirects.** Copilot Studio does not detect these — they cause infinite loops.
6. **System topics not customized.** Every agent going to UAT must have `Greeting`, `Fallback`,
   `End of Conversation`, and `Escalate` customized per `ARCHITECTURE.md §9`.

#### 🟠 Warning — degrades behaviour

7. **Trigger phrase count < 10** per custom topic. Fewer phrases give the NLU engine insufficient
   signal. Minimum 10–15 for production. See `topic-design.md §1`.
8. **Topic overlap not checked.** If trigger phrases overlap with another topic, misrouting happens.
   Verify with the **Topic Overlap** view in Copilot Studio before publishing.
9. **Topics > 30 nodes.** Extract sub-flows to separate topics. See `topic-design.md §3`.
10. **Global variable pollution.** Global variables set in one topic and not cleared at `End of
    Conversation` leak into subsequent sessions.
11. **Write operations without a confirmation step.** Any submit/update/delete must show a summary
    and ask the user to confirm. See `topic-design.md §2`.
12. **Teams-deployed agent missing production hardening.** Check against the 8-pattern framework in
    `teams-production-hardening.md`: reinstall handling, inactivity reset, session-expired card, global
    context init, Reset Conversation, Start Over with diagnostics, OnError with telemetry,
    suggested prompts.
13. **Azure OpenAI agent without RAI error handling.** `OnError` should classify
    `ContentFiltered` subcodes and return category-specific messages. See `rai-error-handling.md`.
14. **Generative answers used for regulated content.** Compliance-sensitive content (legal, HR
    policy, financial) must use authored topics only. See `ARCHITECTURE.md §3`.
15. **Single-word trigger phrases.** Too ambiguous — causes misrouting.
16. **Variable naming convention violations.** `Topic.PascalCase`, `Global.PascalCase`,
    `spr_camelCase` for environment variables. See `naming-conventions.md`.

#### 🟡 Suggestion — Track B

17. **Topic count > 15** without grouping — consider multi-agent extraction or topic folders.
18. **Slot-filling without input validation** — missing condition checks on collected values.
19. **Adaptive Cards on channels that don't render them** — check channel support before using.
20. **Knowledge source too broad** — overly broad SharePoint scoping reduces answer relevance.
21. **No PPAPI evaluation suite** before environment promotion.

## Output artifact

Save to `.sopra/workflow/review-agent-yaml/review-{timestamp}.md` containing:

- Agent name, project path, architecture (classic / agentic-loop)
- Component inventory (counts by kind)
- Findings table: severity, file/topic, finding, recommended fix
- Detailed findings with exact file paths and YAML/topic excerpts
- A go / no-go verdict for push (agentic) or for UAT promotion (classic)

## Rules

- Read-only. Never modify the agent. Fixes belong in `implement-plan`.
- Quote the exact file path, topic name, and YAML key for every finding.
- Never suggest edits under `.mcs/`.
- Cite the Sopra guide section behind each finding.
- Use Track A checks for agentic-loop agents. Use Track B checks for classic agents. Never mix.
